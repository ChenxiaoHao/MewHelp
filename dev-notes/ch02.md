**④ 翻车与返工（本任务翻车最多，全部记录）：**

1. **docker pull 失败**：`failed to decode referrers index: invalid character '<'`——daemon.json 配了 18 个镜像加速器，坏的对 OCI referrers API 返回 HTML。绕行：直接 `docker pull docker.m.daocloud.io/library/mysql:8.0` + `docker tag` 回 mysql:8.0。

3. **种子数据双重编码（大坑，两轮返工）**：首启后 aiomysql 读出"售后"是 latin1 mojibake，HEX=C3A5E2809D…（期望 E594AE…），ENUM 定义同样乱码；docker exec 里 CLI 看着"正常"是因为同一个 latin1 客户端显示时抵消了。根因：docker-entrypoint-initdb.d 执行 .sql 用的 mysql 客户端 character_set_client=latin1，UTF-8 文件被当 latin1 二次编码入库。修复尝试一：挂 db/my.cnf 到 /etc/mysql/conf.d → **失败**——Windows bind-mount 单文件权限 0777，容器日志明示 `World-writable config file '/etc/mysql/conf.d/zz-charset.cnf' is ignored`（mysql 客户端安全策略忽略全局可写配置）。最终修复：删除 my.cnf 挂载，服务端加 `--skip-character-set-client-handshake`（忽略客户端字符集声明，强制所有连接走服务端 utf8mb4），`docker compose down -v` 清脏卷重建，一次通过。SQL 文件保持零改动（DDL 原样红线不破）。
4. **Windows heredoc GBK 坑**：`uv run python - <<'PY'` 从 stdin 读脚本按 GBK 解码（实测 stdin=gbk），脚本里的中文字面量必坏 → 验证脚本一律 Write 工具写 UTF-8 临时文件再执行。
5. 小坑两处：验证断言忘 `fetchall()` 返回 tuple-of-tuples 与 list 字面量不等 → `list()` 包一层；种子 SQL 头部注释自带"邮费/运费"字样导致红线 grep 假阳性 → 注释改写为"寄递费用相关字样"。
